# Agent Note: 一条可交互回复，是整页装在一次工具调用里

Status: implemented

## Problem

桥能向用户提问（§11）、能推审批（§3）、能让锁屏上的实况卡亮起来（§29），但没有一条通道让 agent 把一块界面交进会话。`ask_user_question` 携带的是一道题加一组选项，这套词汇里没有图表、表单或可操作的列表的形状。于是手机端始终是一份带卡片的纯文本转录：agent 能描述一张表，永远没法让人去碰它。

## Decision

远端面新增第三种认领——第 35 节 `ui.v1`：一个 `ui.request` 主题用来公告一张卡，一个 `ui.event` 方法让卡里的第一个动作成为发起它的那次工具调用的结果，外加一个只读的 `ui.list` 用于对账。两个能力名（`ui.v1`、`ui.list.v1`）追加在公告列表末尾，`hello.r.minor` 为 21，第 1 至第 34 节的任何帧、字段、方法、主题与错误码都不变。带节号的引用指向客户端协议文档（iOS 仓的 `docs/protocol-v1.md`）；那条文档拥有线路可见的一半，本条拥有桥侧的理由。

呈现是一条新通道，不是把提问通道泛化。提问通道是对宿主 `user-questions/request` waterfall 的一次认领，其线路词汇是一道题加它的选项（[提问走桥](../architecture/2026-10-17-user-questions-over-the-bridge.md)）；把它撑到装一整页加任意事件，要么给每个客户端塞一个必须忽略的字段，要么把一个已上线、有测试的形状换成一个联合体。两条通道各有自己的认领表与结算方式，提问那条因此一字节不变，没声明能力的客户端也完全不受影响。

载荷是一份完整的自包含 HTML 文档，内联在帧里，上限 256 KiB UTF-8。它不是一套组件 JSON 方言：当需求是图表、按钮、表单与列表操作时，没有任何闭集能替 agent 预先决定它画得出什么，而每一次新需求都会变成两个客户端各写一遍的新组件。HTML 还把页面的渲染留在写它的那个 agent 手里。帧里刻意没有 `url`：发布地址的宿主等于让客户端去取一份到达与否宿主无法担保的内容，所以页面要么内联到达，要么根本不出现。

第一条 `ui.event` 即结算。那个动作成为工具结果，卡片被公告 `settled`，此后同一 call id 的每个事件都回 `ui-settled`。需要继续接受动作的页面是**再呈现一次**，一次认领只承载一个动作。一次调用一张卡，是结果正文得以保持三种形状的闭集（一个动作、一次释放、一次拒收）的原因，也是桌面端能直接从它本来就有的那行工具卡里画出这张卡的原因。

`ui.list` 存在，是因为客户端的寿命可以长过它对线路的记忆。一台重启的手机盘上可能留着一张 `open` 的卡，而桥在 App 被挂起期间已经撤回了它，线路上没有任何东西会说这件事。客户端能拿来猜的三个信号——会话在不在跑、卡有多旧、roster 里有没有那一行——全部滞后，这正是第 24.5 节否掉启发式的原因：猜错的代价是把真活卡变成只读。列表直接答事实：桥此刻仍持有的卡，不认领、不动 deadline、不写任何宿主状态。退休需要第 24.3 节的四个条件全部满足（能力已公告、`ok: true`、`complete == true`、每一行都能解析）；任何一条不满足的这一轮不退休任何卡。

没人能答的卡会被释放，而这次释放被推迟同一个六十秒窗口，也就是扣住一个提问的那个窗口（[认领宽限窗口](../architecture/2026-10-23-user-question-claim-grace-window.md)）。复用 `QUESTION_CLAIM_GRACE_MS` 而不是新增一个旋钮是刻意的：两种认领挡住的是同一件事——agent 的一次工具调用，两者都由同一个“最后一部配对设备离开”触发释放，第二个常量就等于对同一个问题给出第二个答案：手机有多久可以回来。窗口只武装一次，不被后来的离开延长，由一条已配对、声明了该通道并接下重放的连接取消——与提问窗口同一条判据，只是判在声明时而不是认领时——桥卸载时立即释放而不是留一个定时器。

两个上限都在发起端拒收。超过 256 KiB 的页面在任何帧写出之前就按 `invalid-args` 拒掉，也不带展示载荷；事件载荷超过 8 KiB 同样处理。让客户端拒收，等于让 agent 白等一张永远不会来的卡，所以上限属于“等待被创建的地方”。

公告不是协商。没有任何已配对连接声明 `ui.v1` 时，`ui_present` 立刻回 `unavailable`、不扣住任何人——与提问通道的认领排他同一条判据；一帧投不到任何连接时是撤销，不是留着。

## 桌面端只渲染，不作答

Web GUI 没有到这座桥的 socket，它渲染的是一份转录。它从那次工具调用本身认识这张卡：调用进行中读参数，结果落地后读 `meta.ui`——`{key, title?, html, height?, state}`，key 是 `"<sessionId>/<callId>"`。阻塞式呈现只在结算之后才返回，所以这个载荷的 `state` 实际上是 `settled`，它的 `open` 支是将来非阻塞呈现会发布的形状；而在卡还等着的时候，参数是唯一能画出它的材料。

这一行是官方 `tool.call.toolview` 槽里的一次 keyed 注册，key 就是线路上那个工具名 `ui_present`，于是卡的正文画在官方工具行内部，那一行的其余部分仍是官方的。影子化 `tool-call` 渲染器被否决：同一个 cell 只有最低 priority 的条目渲染，没有“画一半交给下一个”的机制，而影子条目不能重复声明官方渲染器已经占用的子槽——影子因此等于复刻整棵官方工具卡。自建专属 `ChatNodeKind` 同样被否决：它可行（节点表是 open interface，装配器是客户端模块），代价是一次 type merge、一次事件注册与一个渲染器，而一次 keyed 注册已经把页面画出来了。

这一行只渲染、不作答。GUI 到 `ui.event` 没有任何路径，而保证是那个否定式的：页面报告的任何东西都不被转发、不落库、不发请求——一个动作只会变成一句可见的话，告诉操作者去手机上作答；页面被沙箱到 `allow-scripts` 且不带 `allow-same-origin`，所以文档是不透明源，GUI 自己的存储与 cookie 够不着。“没有答案离开这一行”是一个真实的承诺；“控件被禁用”不是——父窗口无法禁用一个不透明源文档里的控件。

## 本地槽口 seam 是技术债

`packages/dsh-remote-bridge/src/client/toolview-slot.ts` 把 `ctx.slots` 收窄到这次注册用到的两个成员，并在本地声明这个槽自己的形状，因为声明 `tool.call.toolview` 的包 `@deepseek-ai/dsh-client-ui-tool` 并未装进本工作区。type-only 导入本身就是一次新增依赖，而本地 `declare module` 扩展会重复另一个包拥有的契约，并在两者同时加载的地方与真实声明冲突。这个 seam 携带三件事（阶段名、keyed 分发、locale 座位），上游改这三件事的形状就是改这个文件。等这个包下一次做依赖调整，seam 会被 `PropsRuntime<'tool.call.toolview'>` 与带类型的 `register` 重载取代。

## Testing

`packages/dsh-remote-bridge/tests/ui.spec.ts` 共十五条，跑在真实 socket 上：公告的能力列表；声明过的手机收到整页；动作成为工具结果；重复点一张已结算的卡回 `ui-settled`；对本桥从未认领的 call id 回 `ui-unknown`；线路上没人、以及已配对但未声明能力时回 `unavailable`；超过上限的页面回 `invalid-args`；超过 8 KiB 的载荷回 `invalid-args`；`ui.list` 只读出 open 的卡且不改变任何东西；`meta.ui` 以宿主 call id 为 key；宽限窗口释放；重连后重放；窗口内手机回来；取消回合后释放且不编造动作。

`tests/ui-card.spec.ts` 与 `tests/client-ui-present-row.spec.tsx` 覆盖转录读取与那一行本身，不需要浏览器工具层：只有参数的阶段；结果载荷压过参数；按 UTF-8 字节计的精确上限；帧文档；主题令牌；量出来的高度；沙箱属性；来自别的窗口的消息被忽略；以及按线路工具名做的那一次 keyed 注册。

## Alternatives considered

**原生组件闭集——每个客户端各画一套 JSON 图表/表单规格。** 否决：agent 需要的是一个通用面，图表、按钮、表单与列表操作，新形状还会持续到来。闭集等于替 agent 决定它被允许画什么，并把每一次新需求变成在手机与 GUI 上各实现一遍的新组件。

**保留 fenced 代码块约定，由客户端从转录里解析出页面。** 否决：桌面端会看到裸围栏，或者需要同一个第二解析器；而流式半截文档根本没法解析——卡片只能在整个回合结束后才存在，而那正是没人等着它的时候。

**把提问通道泛化成能装一整页。** 否决：那条通道的全部形状就是一道题加选项，它的认领是对宿主提问 waterfall 的认领；加宽它会给每个现有客户端塞进必须忽略的字段，并让一个能力名同时意味着两件事。页面需要自己的结算、自己的对账读取和自己的上限。

**影子化官方 `tool-call` 渲染器。** 否决理由是机制不是口味：一个 cell 只渲染最低 priority 的条目，没有把画了一半的 cell 交出去的机制，影子也不能声明官方渲染器已经声明的子槽。结果是复刻整棵官方工具卡，只为改其中一行。

**给卡片新增专属 `ChatNodeKind`。** 否决：改动更大而收益更小——一次 type merge、一次节点装配注册与一个渲染器，对上一次 keyed 注册；唯一的好处是卡不再寄生在工具行里，而发起它的那次调用本来就在那一行。

**一张卡多条事件——调用一直开着，直到页面说它结束了。** 否决：“这次呈现什么时候算完”在线路上没有诚实的答案，而一个没人关闭的开着的调用就是一个被永久卡住的 agent。卡片由第一个动作结算，需要持续可交互的页面就再呈现一次，这把寿命交到发起方手里，而不是交给一个超时。

## Consequences

- 桌面端展示一张操作者必须拿起手机才能用的卡。这是第 35 节被接受的形状：作答需要那条 socket，而为 GUI 再开一条结算通道，正是本仓已经回退过一次的跨面冲突（[提问走桥](../architecture/2026-10-17-user-questions-over-the-bridge.md)）。
- 页面可以加载 `https:` 子资源，所以一张呈现出来的页面可以把它持有的数据发到外部地址。缓解手段是非持久站点数据、页面内没有可用的用户凭据、以及卡头对用户可见——而不是拦网络，拦网络等于连同一个决定换来的 CDN 场景一起去掉。
- 宽限窗口让一个 Mac 用户在手机已离开的卡上多等最多六十秒，与扣住一个提问完全一样。窗口就是旋钮，而且它是提问通道那个旋钮，不是第二个。
- 上限属于发起方：忽略工具描述的 agent 会被按 `invalid-args` 拒收，而不是拿到一张被截断的页面，并且它能把这个与 `unavailable` 区分开。
- 槽口 seam 镜像了一份上游形状，所以一个改了阶段名或去掉 locale 座位的 SDK cohort 会打断这里的注册。这是不引入那个依赖的已记录代价；文件里点名了它镜像的三件事，所以那次改动是一次查表而不是一次发现。
