# Agent Note: dsh-usage 的按日用量选择器（用量页签与 Token 银行）

Status: implemented

## Problem

自[插件首发](../feature/2026-08-29-usage-statistics-plugin.md)起用量台账一直是持久化的：每次折叠都按本地日写进 `$DSH_HOME/dsh-usage/usage-ledger.json`，并按 `retainDays`（默认 180 天）保留。但浏览器能拿到的只有今日（`usage.today`）、近 30 天聚合（`usage.range`）与全台账聚合（`usage.all`）。用户问「周二花了多少」时，页面上只有今日卡片、30 天柱状图或累计总量，某一历史日的分 provider / 分模型明细完全取不到——分区看上去像一个没有持久化的插件，因为屏幕上从不出现过去的日子。

## Decision

「一天」成为一等窗口，按需提供，而不是预先聚合进轮询文档：

- **`usage.availableDays?: string[]`**（新增、可选）随 overview 下发：保留期内所有有记录的本地日，升序，越过 30 天趋势上限直到整个保留窗口。它就是两个选择器的选项列表，每天只花几个字节。
- **`GET /api/dsh-usage/day?date=YYYY-MM-DD`**（新增，`packages/dsh-usage/src/host/routes.ts`）以 `{ ok: true, day: UsageDayView }` 返回单日——正是 overview 已经为今日提供的 `{ date, totals, providers }` 形状，因此被选中的那一天与实时的今日卡片是同一种文档。该路由沿用家族信任围栏（回环，或配对设备的 cookie），对不是真实本地日的 `date` 返回 400，被清理或从未记录的那天返回全零日。聚合由 `UsageService.day()` 暴露；`src/core/ledger.ts` 的 `isLedgerDateKey` 是唯一的日期键校验器，与持久化文档读取共用。
- **分区不缓存日数据。** `useDayView` 按需拉取被选中的那一天，取消被取代的选择，并把失败的加载作为自己的错误行上报。今日从不请求：overview 已经实时带着它，切回今日是瞬时的，并继续随 10 秒轮询增长。
- **两个选择器共用一个 hook。** 用量页签的卡片在今日与被选中的日之间切换（标题、合计、分 provider 行、日级消费标签都跟随选择；峰谷计价行留在今日，因为它描述的是当前时段的计价）。Token 银行的选择器多一个「全部保留期」选项，于是票券可以按某一天或整段窗口铸造；其真实花费观测行——自首次余额观测起的累计值——只在整段窗口下展示。
- **被选中那一天的 provider 行允许换行。** 日行的读数是「tokens · 调用次数 · 消费」，比今日的单 provider 行更长，因此共用的 provider 行在窄面板里把读数折到下一行，而不是压到 provider 名字上。该规则纯属布局，作用于所有 provider 行。

## Alternatives considered

- **把每个保留日都塞进 overview 文档**：一次请求、零新路由。落选：分区打开时 overview 每 10 秒轮询一次，而整个保留窗口最多 730 天的分 provider / 分模型明细，是极少被查看的单日数据的几十倍负载。日期清单很便宜（字符串），单日明细不是。
- **覆盖整个保留窗口的自由日期选择器（`input type=date`）**：任何一天都能到达，包括没有用量的那天。落选：台账只保存有记录的日期，范围里绝大多数是空卡片；原生日期输入还带来与区域设置相关的解析问题和每个页签多一个控件。下拉框也不会给出宿主只会返回全零的那一天，读起来是「我能查看的那些天」而不是「一张日历」。
- **把 30 天趋势窗口放大到覆盖保留期**：趋势是窗口上的柱状图，不是按日浏览器；放大只会把一年的柱子堆到屏幕上，仍然给不出那天的分 provider 行。
- **在 store 上做客户端日缓存**：用户在两个日期间来回切换时能省一次请求。落选：store 的职责被定义为分区本地的 overview 快照加取数生命周期，而分区组件本身跨页签切换不卸载，缓存等于为一次本就很便宜的回环请求增加共享状态。
- **在浏览器里从持久化台账文件推导历史日**：构造上不可能——文件在宿主侧，而它的内容正是台账路由已经在守护的东西。

## Consequences

- 两个选择器只列有记录的日；没有用量的那天不会出现，被保留期清理掉的那天读到的是空态或全零卡片，而不会显示成别的日期。
- 日路由是第三个受围栏的端点：每日事实与 overview 同样私密，因此 `isUsageAllowed` 以完全相同的方式守护它（已配对的局域网设备放行，其余未配对请求保持 403）。
- 旧宿主文档没有 `availableDays` 时根本不渲染选择器，旧浏览器半区也会忽略这个新路由；两个方向都保持兼容，因为新字段可选、新路由只从已存在的选择器发起。
- 被选中的那一天是单次请求的快照：10 秒轮询不会刷新它，对已结束的一天这是正确的，进行中的那一天由今日路径负责。
- `tests/usage-service.spec.ts`、`tests/routes.spec.ts` 与 `tests/section-card.spec.tsx` 分别钉住单日聚合、查询闸门与围栏、以及两个选择器的切换行为。
