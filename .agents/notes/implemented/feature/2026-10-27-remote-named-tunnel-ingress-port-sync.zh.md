# Agent Note: 命名隧道的 ingress 端口跟随实际绑定端口，仅更新

Status: implemented

## Problem

命名隧道是本插件为操作者自有域名提供的模式：公网主机名永久固定，因此已配对的手机在 `dsh web` 重启后仍保留书签与配对 Cookie（这一点的围栏后果由[隧道重连信任记录](../bug-fix/2026-09-13-remote-web-ui-tunnel-reconnect-trust.md)承载）。主机名固定，它的 ingress 规则却不然。规则里写的是 `http://127.0.0.1:3080`，而之后的 `dsh web` 可能在别处监听——操作者加了 `--port`、换了 profile、旧端口被另一个实例占用。此时 Cloudflare 对一个本插件仍宣称已发布的主机名回 502，而包内没有任何一处看得见它：连接器归插件，ingress 归控制台，手动改一步又很容易忘，因为端口变化时界面没有任何变化（工单 #1948）。

反向的失效比 502 更糟。一个靠整体重写文档来「修好」它的插件可能删掉规则、重排 ingress、替换掉 catch-all——那是被诊断功能造成的、落在同一主机名上其它服务身上的故障。

## Decision

`ingressSync`（默认关闭）是本包通往隧道配置的唯一写入路径，并且在构造上就是仅更新。`src/ingress-sync.ts` 拥有一个纯 planner 与一个单飞 runner：读取文档、证明 plan、只写有证据的漂移、再把文档读回。

plan（`planIngressUpdate`）只有三种结果：

- **unchanged**——匹配到的规则服务已经指向实际端口。不写，也不向调用方提供任何文档。
- **apply**——一份完整文档，与读到的文档恰好只在同一处不同：主机名等于配置主机的规则的 `service` 字符串。证明是机械的（`withoutTargetService` 把该键从两份文档里替换成标记后比较规范化 JSON），因此这条不变量是断言而不是注释。这条服务还必须属于本机：它的主机得是回环字面量（127.0.0.0/8 中四段都是真实 0-255 八位组的地址——所以 `127.9.9.9` 通过、`127.999.999.999` 不通过——、`::1`、或 `localhost`）或本机自己的某个局域网 IPv4 地址（`lanIPv4Addresses()`，每次运行现读）。邻居的地址、别的网段的地址、或 `dsh-nas` 这类 DNS 名一律判为冲突——那个端口服务的是那个地址本身，改它的端口等于弄坏一个本插件并不拥有的服务。
- **conflict**——不给文档。缺失 `ingress`、`ingress` 不是数组、规则不是对象、任一主机名含通配符、目标主机名缺失或重复、最后一条规则带主机名（没有 catch-all）、服务不是 http(s) 源、或服务托管在本机之外的任何地方。

发现机制是显式字段而不是推导：`cfApiToken`（设置密文）、`cfAccountId`、`cfTunnelId` 三个独立字段。命名隧道的运行令牌（`tunnelToken`）从不被解析来取材——它的内部格式不是本包拥有的契约，且这么做只有在浏览器半区才顺手，等于把账户 id 放进页面状态。

收敛是一个状态机（`off`、`waiting`、`applied`、`failed`、`conflict`），带三条插件其余部分依赖的性质：

- **实际绑定的端口是唯一目标事实，而且它得是一个真端口。** `ctx.webServer.port` 还不存在时 runner 一个请求都不发并上报 `waiting`；一次半读的 webServer 递来 `NaN` 或 `Infinity` 会被归一成「没有端口」，而不是变成一条关于本插件自身配置的冲突。插件既有的端口静置重规划（启动快速隧道的那一套）一秒后把端口送到。它自己没有第二条重试回路。
- **单飞 + generation 守卫。** 每次 schedule 递增 generation，且每一个最终「没有目标」的分支——总开关关闭、没有主机名、没有有限端口、设置不全——都经同一条 `invalidate()` 作废在途运行，因此被其中任一分支取代的运行既不能写入、不能记录收敛、也不能上报 applied。运行在每次请求尝试之前校验它——所以 429/5xx/网络退避排下的那次重试无法活得比它的目标更久——并在它唯一那次写入之前再校验一次。落在飞行途中的设置保存或端口静置会丢弃过期目标而不是把它写下去，被丢弃的请求什么都不发布（由排队的运行上报）。300 毫秒的短去抖把一次保存产生的突发合并成一趟。已收敛目标被记录的身份里包含 API 令牌的截断 SHA-256 摘要而非令牌本身：换凭据会重读文档，同一凭据不会。
- **有界且诚实的失败。** 401/403 以及除 429 外的其它 4xx 一律终止（`failed`）。429/5xx/网络最多重试两次，超过即上报最后状态。冲突绝不自行重试。

写入是一次全量 PUT，因为 API 没有单规则补丁；随后恰好读回一次。读回不一致即 `conflict`（`verify-mismatch`）且绝不重写：同一份隧道文档只有一个写入者，并发写入者（控制台、另一台机器上的同一同步）必须由人核对，而不是被循环去争。快速隧道永远不是目标：`autoTunnel` 每次启动铸造新主机名并占用公网地址，那里同步读作 `off`，而不是去改一条无关的隧道。

状态帧挂在 `PairingSnapshot.ingress` 上（因此 `/api/pair/status` 只会交给桌面或已配对设备，永不交给未配对的隧道访客），设置卡片把它渲染在开关旁边。它携带公网主机名、绑定端口、两个服务字符串、规则位置与原因。那两个服务字符串都脱敏了 userinfo：隧道服务可以为受保护的源带上 `user:password@`，写入会逐字节保留它，而任何审计字段都不显示它。状态帧绝不携带凭据。默认传输层本身拒绝构造发往 `https://api.cloudflare.com` 以外任何源的请求，所以即使调用方拼出这样的 URL，令牌也无法抵达别的主机。

## Testing

`tests/ingress-sync.spec.ts`（53 个用例，不触网）钉住两层：

- 纯 plan：单点差异不变量、未被触碰的规则/catch-all/顶层键、unchanged 判定、每一种冲突形态连同它的错误码与「不提供文档」、回环与本机局域网地址白名单（`192.168.1.5` 与 `dsh-nas` 都按拒绝覆盖），以及审计字符串里的 userinfo 脱敏——同时写入仍保留它；
- runner：关闭、未配齐、缺主机名、缺端口、端口非有限数时零请求；无漂移时只读一次；有漂移时 GET/PUT/GET 且 PUT 体精确；401/403 在第一次调用即终止；429 与网络失败三次尝试封顶；写入被拒判为冲突；读回不一致判为冲突且没有第二次写入；已收敛目标在凭据未变时不再重读；失败目标在下一次 schedule 重试；过期 generation 在其唯一写入前被丢弃、并在待决的 429 退避期间再次被丢弃（过期端口永不 PUT、只有排队目标会写，且被打断的 429 也不会被发布成失败帧）；在途目标被清空——清 token 或清 hostname——会作废在途运行，使它既不写入也不上报 applied，终帧就是被清空后的配置；live 端口归一器把 `NaN`/`Infinity` 变成「没有端口」，从而走到静置重试；待决的退避等待在 dispose 时被释放且不再发后续请求；令牌只出现在 `Authorization` 头、不进任何状态帧、不进任何审计字段。

`tests/routes.spec.ts` 钉住 `/api/pair/status` 的分层：未配对的非回环调用者拿不到 `ingress`（也拿不到 `service`/`hostname`），而已配对设备能读到该帧。`tests/pairing.spec.ts` 钉住状态帧进入快照且不重复 emit，`tests/settings-surface.spec.ts` 钉住四个 volatile 卡片字段与令牌的 secret role。

## Alternatives considered

**交给控制台，并把手动那一步写进文档。** 已否决：手动那一步恰恰是静默失效的那种。端口变化时界面没有任何变化，操作者只会从一个本插件仍在宣传的主机名的 502 上得知。

**改用本地 ingress 文件运行连接器（`cloudflared tunnel --config`），而不是远程托管配置。** 已否决：它需要隧道的本地运行凭据（不是控制台令牌）并分叉了事实源——在控制台管理路由集的部署会静默丢失之后每一次控制台改动。

**只补丁那条被改的规则。** Cloudflare API 没有单规则补丁：唯一可写的表示就是整份配置文档。这正是 plan 必须证明文档其余部分、而不能假设它的原因。

**反复写入直到读回一致。** 已否决：当存在第二个写入者（开着的控制台标签页）时，这个循环会和人对打甚至来回振荡，并且会把冲突伪装成瞬时错误。

**从隧道令牌推导账户与隧道 id。** 已否决：令牌的内部格式由 Cloudflare 决定，解码总得落在某处，而顺手的那处是浏览器半区——等于为一个操作者可以从控制台复制一次的值，把账户 id 放进页面状态。

## Consequences

- 插件现在能逐条隧道上报：已发布的主机名是否真的抵达本机端口，没抵达时给出原因——这个状态帧正是 502 过去缺失的审计线索。
- 冲突是停止而不是重试：既开着控制台又开着同步的部署会看到 `verify-mismatch`，直到其中一边关闭。这是有意的取舍，代价的另一端是静默覆盖。
- 账户令牌是本包里的第二份凭据。它的影响面就是操作者授予的 Tunnel:Edit 权限；它以设置密文存储、只发往 Cloudflare API，从不写日志、不在界面渲染。
- **被明确点名的覆盖缺口**：本次交付没有做真实 Cloudflare 验收。所有路径都由注入 fetch seam 的离线测试覆盖，发布说明与 issue 都已写明 #1948 不得仅凭这批证据关闭。
- 残余风险：API 没有条件写入，因此落在读取与 PUT 之间的写入者只能在事后（以 `verify-mismatch`）被发现，永远无法事先阻止。
