# Agent Note: SDK cohort 0.1.7-rc.2

Status: implemented

## Problem

The integration line declared `0.1.7-rc.1` while the official family published `0.1.7-rc.2` on 2026-09-24 (npm `next`, host CLI out at 14:18Z), one day after the rc.1 cohort landed. Staying put would have left the family's machine-readable floor pointing at a host that stopped receiving fixes on the same day the line moved, and the release candidate is not an empty delta: the host carries a new dependency (`@deepseek-ai/dsh-experimental-auto-review`), the web app gains `dsh-schedule`, `dsh-time-context`, `dsh-client-shortcuts` and `dsh-client-ui-shortcuts`, and `dsh-client-ui-primitives` imports a further face its manifest still omits.

The publish also arrived in two pieces. The SDK packages started appearing at 13:58Z and the host at 14:18Z, so a cohort check run during that window reports a half-published family; the check has to be re-run against the registry rather than inferred from a release tag.

## Decision

The whole cohort moves to `0.1.7-rc.2` in one change, in the isolated worktree `sdk/0.1.7-rc.2` based on the local `dev` tip (`46ee2736`, two unpushed commits ahead of `origin/dev`), so the shared checkout and the running GUI are untouched until integration. It is the second move on this line and follows [sdk-cohort-0.1.7-rc.1](2026-09-23-sdk-cohort-0.1.7-rc.1.md), whose note keeps owning the rc.1 move; this note owns rc.2 and supersedes none of it. The base carries the Electron desktop removal, which is why this cohort move has five host-floor surfaces instead of six (see below).

### One cohort, one literal

318 specifiers across 41 files: the fifteen family manifests, the plugin scaffold, the shared workspace package, the `dsh.engines.dsh` floors with their identical `@deepseek-ai/dsh` host peers, the release-age exclusion ledger, the two `packageExtensions` keys re-keyed to the new cohort, the root README badges, the CI and release mount-smoke pins, the cohort literals in `shared/web-platform.ts`, `shared/tests/web-platform.spec.ts`, `tests/e2e/mount.e2e.ts` and `scripts/rollout-verify.test.mjs`, and the cohort prose in `docs/publish-prep.md`, `docs/plugins.md`, `packages/dsh-web-all/aggregate.yml` and the three package README pairs (with their pairing records re-recorded). `@deepseek-ai/cordis` (4.0.4) and `@deepseek-ai/schemastery` (3.18.4) do not move: their lines are independent and the cohort's own peers still name them.

### Two surfaces were verified against the published artifacts

- **The frozen module table is unchanged.** Extracting `@deepseek-ai/dsh-web-frontend` at both cohort versions shows the same nine `staticModules` specifiers; only the minified identifiers differ. `shared/web-platform.ts` therefore keeps its list and moves only its provenance comment. The new `@deepseek-ai/dsh-client-shortcuts` is an ordinary client plugin injected by the sidebar and workspace rows, not a static module.
- **The primitives patch gains a face.** `@deepseek-ai/dsh-client-ui-primitives@0.1.7-rc.2` imports `@deepseek-ai/dsh-util-code-language`, published for the first time at rc.2, and the manifest still declares no runtime dependencies. The `packageExtensions` entry adds that exact pin. The pre-existing upstream packaging defect (undeclared `immer`/`zustand` in `dsh-client-store`, and the long list in `dsh-client-ui-primitives`) survives rc.2 unchanged, so no patch is dropped.

### The upstream publish gap, and how verification proceeded

`@deepseek-ai/dsh@0.1.7-rc.2` **cannot be installed from npm**. `@deepseek-ai/dsh-web-app@0.1.7-rc.2` declares an exact dependency on `@deepseek-ai/dsh-client-ui-settings-account@0.1.7-rc.2`, which upstream never published (that package's `next` and newest version are both `0.1.7-rc.1`), so both `npm install -g @deepseek-ai/dsh@0.1.7-rc.2` and the CI/release mount-smoke step fail with `ETARGET`. The omission is not a rename: `dsh-web-app` still lists all eleven `settings-*` rows at rc.2 and removed none, while adding four packages. All 81 direct dependencies of the host resolve; only this transitive edge is missing.

The global CLI therefore stays at `0.1.7-rc.1` (npm leaves no partial state), and the host-dependent gates run against a scratch host installed into a temporary prefix with one documented override — `@deepseek-ai/dsh-client-ui-settings-account` pinned to `0.1.7-rc.1` — passed to the repository's own smoke lane through its `DSH_CMD` switch. That is enough to exercise the real rc.2 host and this checkout's built plugins; it is not enough to ship, because the release pipeline installs the pinned host with no override. **Upstream published the missing package at 14:32Z the same day, so the gap closed within the hour: the global CLI moved to `0.1.7-rc.2`, the registry install path replaced the scratch override, and this cohort shipped in the 0.4.2 release.**

### Host-floor surfaces

Five of the six surfaces named by [dsh-host-floor-tracks-cohort](2026-09-01-dsh-host-floor-tracks-cohort.md) move: the engines floors, the host peers, the root README badges, the CI/release mount pins and the `docs/publish-prep.md` sentence. The sixth — the desktop host payload pin in `desktop/runtime/host/package.json` — no longer exists on this base, because the Electron desktop application and its packaging lane were removed in `64beab4a`; there is nothing left to move, and the consistency requirement it carried is retired with it. The satellite peer floors recorded in `pnpm-lock.yaml` still read `>=0.1.7-rc.1`: they belong to the satellite packages, which move to the aligned version in their own repositories.

## Alternatives considered

**Wait for the missing package before bumping anything.** Rejected: the cohort move is a repository-side change whose verification does not depend on the one absent row, and holding the branch would leave the family declaring a floor the line has already left. The release is gated separately, which is where the missing package actually bites.

**Ship 0.4.2 on `0.1.7-rc.1` and take rc.2 later.** Rejected by the operator: 0.4.2 carries the rc.2 cohort, so the release waits rather than shipping a cohort the SDK has already superseded.

**Override the missing dependency in the release pipeline.** Rejected: the pipeline installs the pinned official host as the user installs it. An override there would ship a host composition that no user can reproduce, hiding an upstream defect behind a local patch.

**Move `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` with the cohort.** Rejected on the same ground as the previous cohort: neither publishes a `0.1.7-rc.2`; their lines are independent and the cohort's peers still constrain them.

**Remove `dsh-plugin-manager`'s compatibility pre-check now that the official preflight decides the same question.** Still rejected, unchanged from the rc.1 record: the two rules read different fields, and the GUI evidence needed to prove the official refusal on the npm-published web runtime is unavailable while the host cannot be installed.

## Consequences

- The declared floor, the host peer, the badge and the CI/release mount pins all name `0.1.7-rc.2`, so the repository's stated requirement now leads what a user can install. That is deliberate and temporary: it is exactly the state the upstream gap creates, and it is recorded here rather than papered over.
- The upstream gap closed the same day: `@deepseek-ai/dsh-client-ui-settings-account@0.1.7-rc.2` appeared at 14:32Z and 0.4.2 shipped on this cohort. The release pipeline then failed its strict registry assertion on propagation lag alone — twelve of the fifteen packages appeared inside its budget there and the remaining three, the aggregate included, only after it, the aggregate taking about eighteen minutes against a budget of roughly eleven. The release was completed from the same commit by running the mount smoke and cutting the Release; widening that assertion budget is open follow-up work, not a cohort defect.
- The satellite packages still declare `>=0.1.7-rc.1` as their host peer. They converge on the aligned version when the four satellite repositories release `0.4.2`, which the release flow requires before this repository tags.
- Local profiles keep their `@deepseek-ai/*` shadow copies on the rc.1 cohort until the global CLI moves and the operator restarts. No profile surgery is possible or needed while the CLI cannot be installed.

The registry install of the pinned host and the release's own mount smoke are verified once the gap closed: the host installs from the registry with no override, and the smoke lane passes against it with tarballs packed from the release commit. The per-surface GUI comparisons behind the three kept overlap decisions remain the one named gap; they are unverified rather than disproved, and the mount smoke is the depth this change reached.
