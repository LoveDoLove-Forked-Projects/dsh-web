# Agent Note: 临时开放期接收外部 PR

Status: implemented

## Problem

本仓把每一个外部 PR 都关闭。`.github/workflows/reject-non-content-pr.yml` 关闭内容范围之外的 PR，并把四类已迁移的内容贡献——皮肤 / 皮肤中心、新宠物收录、新预设收录、社区插件索引——重定向到各自所属的独立仓；`.github/workflows/reject-docs-pr.yml` 关闭纯文档 PR。对任何非协作者作者，两条工作流都无条件动作，于是维护者要接收一个合规的外部提交，就得先停掉自动化。维护者需要一段有界的窗口：在不改变标准政策、不改变归属边界、不改变证据门禁的前提下接收外部提交。

## Decision

- 两条关闭工作流各带一个显式的顶层开关 `ACCEPT_EXTERNAL_PRS`，由各自的工作流文件读取；临时开放期把它置为 `'true'`，自 2026-10-27 起，由维护者手动收尾。
- 开关为 `'true'` 时，两条工作流对非内容贡献的外部 PR 一概不动：不评论、不关闭、不 `setFailed`；纯文档 PR 同样保持开放。
- 四类内容贡献不受开关影响：这类 PR 仍然被评论、关闭并重定向到对应独立仓。
- 证据门禁 `.github/workflows/pr-contribution-rules.yml` 一个字都不动，所以缺少模板必填证据的 PR 仍会被评论要求补充，只是不再被关闭。
- 恢复方式就是把开关改回 `'false'`：原有拦截逻辑完整保留而非被替换，因此两条工作流的行为与开放期之前完全一致。
- 文档只写临时状态与恢复方式。标准政策的归属见[预设中心卫星仓 Note](../architecture/2026-09-24-preset-center-satellite-repository.md)，不会被改写成「本仓从此接收外部 PR」。

## Alternatives considered

**永久放开本仓。** 否决：维护者要的只是一段临时窗口，而标准政策——内容贡献在各自的独立仓、本仓不接收外部直接 PR——并不打算变。永久放开等于改写政策，而不是暂停它的自动化。

**在窗口期直接删掉两条关闭工作流。** 否决：恢复意味着回滚提交，窗口的收尾从两行编辑变成一次历史操作，而且整个窗口期失去内容贡献重定向。

**用仓库变量或到期日自动恢复。** 否决：维护者账号没有 admin，无法设置仓库级或组织级变量；到期日则要在两条工作流里各加日期逻辑，并且需要一个人工维护的提醒，本身仍是手工工作。

## Consequences

- 恢复成本是两行：每条关闭工作流一行开关。其余都不需要回滚。
- 恢复后本 Note 移入 `.agents/notes/archived/`，因为窗口一关，这条已交付的决定就完结了。
- 开放期内 PR 量上升，由维护者按 `scripts/pr-review.mjs` 与必需检查处理，流程与之前一致。
