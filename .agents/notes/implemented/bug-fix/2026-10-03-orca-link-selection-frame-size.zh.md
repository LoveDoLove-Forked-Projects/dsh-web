# Agent Note: orca-link 的选中框按整行而非图片取尺寸

Status: implemented

## Problem

orca-link 皮肤里有两个选中高亮和它们所属的画面不匹配。两者都以「框和图片对不上」的形式被报上来。

**角色周围的舞台框。** 指针悬停在新会话舞台上时出现的角括号框，实测是 (22, 58) 处 250 x 132，而角色画在同一起点的 250 x 240 盒子里。于是框把角色从腰以下切掉了，那个蓝色角标三角也悬在画面中部、紧挨着角色。对照状态图集（1888 x 2360，8 x 10 格、每格 236px）测量，角色墨迹占该格的 216 x 220，也就是约 90px 的画面掉在了自己的框外面。

**左上角字标周围的品牌框。** DSH 字标的键盘选中高亮其实是宿主自己的 `:focus-visible` outline，画在整行宽度的 `wide` 控件上——216 x 30 对 118 x 30 的字标——于是它横跨大片空白行区域，并把旁边的 LINK ACTIVE chip 一起框了进去。

两者的根因相同：高亮画在了不是图片本身的盒子上。舞台这边，框和命中面是同一个伪元素，所以 #1743 为点击面调出来的高度，也就是用户看到的高度。字标这边，皮肤没有任何规则在这个控件上关掉全局 `:focus-visible` outline，而皮肤自己的舞台框挂在一个够不到品牌按钮的兄弟控件上。

## Decision

**舞台框与命中面拆成两个盒子。** 侧栏根节点现在把画面盒子声明一次，作为 `[data-dsh-surface="sidebar"] > :first-child` 上的 `--orca-art-h`，状态角色按它取尺寸；框读同一个变量，于是高亮正好是画面占据的那个矩形，不会再和它漂移。命中面保持它被裁短的高度和几何不变，并且现在完全不绘制任何东西（只有 content 和盒子），所以 #1743（命中面吞掉前几个插件行）没有可回归的东西：关于命中面的规则一条都没改。角标三角是这套框语言里唯一常驻屏幕、而不是随悬停出现的部分，它移到画面元素自己身上，取画面自己的右下角（`right: 4px; bottom: 3px`）；原来那个独立定位的标记会跟着框的高度一起漂。

**字标框就是字标的盒子。** 同样的做法，落在另一张图上：字标的盒子在 logo 行上以 `--orca-mark-x/y/w/h` 声明一次，字标和行 `:before` 上的新框共同读取，并在品牌控件上关掉宿主 outline，使字标周围唯一的框就是与它同尺寸的那一个。框规则按位置选中行内第一个按钮（`:has(> button:first-of-type:is(:hover, :focus-visible))`），而不是通过 `[data-orca-link-brand]`：框是绝对定位的，会绘制在普通流按钮之上，因此必须退出指针命中；而 `orca-link-hit-targets.spec.ts` 里的守卫会让任何「选择器文本含 `[data-orca-link-brand]` 且带 `pointer-events: none`」的规则失败。

## Testing

- Live GUI（运行中的宿主，端口 3080，orca-link 生效，明暗样式表均经皮肤中心加载）。舞台框在静止、悬停、键盘聚焦下测量：x=22 y=58 **250 x 240**，与角色盒子四边对齐，透明度 静止 0、悬停 .62、聚焦 .92。命中面保持 250 x 132 不变。
- 字标框实测 x=16 y=21 **118 x 30**，与字标自身 rect 四边相等，悬停 .5、聚焦 1，按钮 outline-style 为 `none`。
- #1743 未回归：命中面仍止于 y=190，而第一个插件行始于 y=310；每行中心的 `elementFromPoint` 都命中该行自己的按钮，点击「插件」行正常打开插件面板。
- 点击角色仍能命中新建会话控件；无页面报错。
- 收起栏不受影响：320px 下画面为 0 x 0，框规则解析为 `content: none`（它与角标三角一样限定在 `body[data-orca-sidebar-wide]` 下），收起栏自己的 6px 弹窗标记不变。
- dsh-skins 的 `pnpm test`（776 用例、53 文件）、`pnpm typecheck`、`pnpm skin-center:check`、`pnpm skin-hooks:check` 均通过。

## Alternatives considered

- **把命中面也放大到画面盒子。** 目前否决：侧栏几何只留了画面底边到第一个插件行之间 12px，而 #1743 是真实发生过的吞点击导航 bug。用户问的是看得见的框；等命中面和列表不再共用同一个数字之后，点击面可以再跟上来。两者现在已经分开，需要时那只是一行的后续改动。
- **把舞台框画到角色元素上。** 否决：该元素带有 `clip-path` 擦除动画和透明度过渡，框会跟着画面一起被擦进来，而不是响应指针。
- **把宿主品牌按钮缩到字标大小。** 否决：行的布局归宿主主管，而按钮宽度正是新建会话的命中面；2026-09-10 的 note 已把字标确立为可见入口，命中面不该小于可见控件。
- **用 `:has()` 在字标而非按钮上限定字标框。** 否决：触发状态必须来自按钮，且同一个 `pointer-events` 守卫会让该规则失败。位置写法正是本表已为该行首个控件采用的那个。

## Consequences

- 两处高亮现在都读作它们所属的画面。修复随皮肤资产发布：已安装的皮肤在下一次皮肤更新或重装时生效，文件变更后刷新页面即可（已实测）。
- `--orca-art-h` 与 `--orca-mark-x/y/w/h` 是两张画面盒子的唯一来源。今后改任一画面的尺寸必须走这些变量，否则框与图片会再次漂移。
- 舞台框是纯装饰：它下面的命中面是唯一的指针目标，这把 #1743 从「按数字守护」变成「结构上守护」。守卫用例现在双向断言这次拆分：命中面不绘制任何东西，框是画面的盒子。
