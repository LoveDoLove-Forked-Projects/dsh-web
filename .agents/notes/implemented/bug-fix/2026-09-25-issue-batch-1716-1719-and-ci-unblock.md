# Agent Note: Issue batch 1716/1719 — legacy row strip, mobile drawer dismissal, CI unblock

Status: implemented

## Problem

Ten issues were open on the tracker and no work was in flight. Triage against the current `dev` tip (`48dd55b5`) read every cited source location rather than trusting the report. Three defects were real and reproducible in a checkout; the remaining seven resolved to "already fixed but unreleased", "wrong plugin generation", "needs a product decision", or "duplicate of a removed surface", and were answered on the tracker instead of being coded (see the round's verdict comments on #1701, #1710, #1712, #1713, #1714, #1715, #1717, #1692).

Separately, `dev` itself was red: the `CI checks` job failed on `48dd55b5`, the maintainer's own tip.

**#1719 — the legacy cleanup left half a YAML row.** `stripLegacySkinRows` (`satellites/dsh-skins/src/legacy-bridge.ts`) assumed a `ui-skin-*` row occupied exactly two lines (the `- id:` line and the one below it) and skipped only those two. The host's own tools write three-line rows: the official plugin manager and the aggregate's plugin manager write `{ id, name, disabled }`, and the config editor writes `{ id, name, config }`. A trailing continuation line therefore survived the strip and merged into the entry above it, duplicating that entry's key. The resulting `cordis.patch.yml` parses as `Map keys must be unique`, and the *next* boot dies with `failed to parse patches` — the damage is written on the boot that still starts, so it surfaces one restart later, and repairing the file by hand only restores it until the following boot. Reproduced by running the shipped functions over the reporter's minimal patch: the output carried `disabled: false` immediately followed by `disabled: true`.

**#1716 — the narrow-shell drawer folded on gestures that are not selections.** `installMobileSidebarDismiss` (`packages/dsh-web-all/src/client/index.ts`) treats a click as a selection when it lands inside `[data-dsh-part="sidebar-entry"]` or `[role="treeitem"]`. `stampSemanticParts` marks *every* `[role="treeitem"]` as a sidebar entry, and a workspace group row — a `treeitem` whose `aria-expanded` toggles in place — plus the row's actions menu both sit inside that subtree. So tapping the group to expand it folded the drawer in the same frame (hiding the rows the tap had just revealed), and tapping the row's ellipsis discarded the menu before it could be used. Both gestures are the ones the reporter described as "the group will not open" and "the three dots do nothing".

**The red `CI checks` job.** `packages/dsh-update/tests/client-entry-desktop.spec.ts` pinned its jsdom origin at `dsh-app://app/`, an opaque origin. jsdom's own `localStorage` getter throws `SecurityError: localStorage is not available for opaque origins` there, and vitest reads that property while populating a jsdom environment's globals — so the worker died during environment setup and vitest reported the file as "failed to start" rather than as a failing test. `pnpm test` aborted on that package while its other 86 assertions passed. This was pre-existing on `dev` and not caused by the round's other work.

## Decision

**#1719 — a legacy row is removed as a whole block.** `stripLegacySkinRows` consumes every line indented deeper than the row's `- id:` line, blank separators included, so nothing of a removed row can duplicate the entry above. The block scan captures the id line's own indent (`/^(\s*)- id:/`) instead of assuming column zero, which keeps the fix correct inside an indented `- insert:` block. Cleanup still rewrites the file only when the text actually changed, so a clean patch stays byte-identical. Fixed in the owning repository (`zhu1090093659/dsh-skins@c5d2a56`) and pinned here by moving the gitlink; four tests cover a three-line row at top level, a three-line row inside an insert block, a following row across its blank separator, and a continuation line belonging to the surviving row, and all four fail against the previous source.

**#1716 — a group row and its actions are not selections.** The group row returns early unless the tap is the row's trailing new-session button, which navigates away and keeps the fold; a session row wins over an enclosing group row, so selecting a session inside an expanded group still folds. This mirrors the distinction `packages/dsh-remote-web-ui/src/client/mobile-adapt.ts` already draws for the same workspace row, so the two adaptations of the same list agree. The regression test drives four gestures — group row, menu trigger, new-session button, session row — and the group-row case fails against the previous source.

**The desktop-page spec installs its scheme instead of pinning an opaque origin.** `client-entry-desktop.spec.ts` replaces the ambient `location` for the duration of one test and restores it in a `finally`. The plugin reads the scheme through `pageProtocolOf()`, which takes a window-like object, so the same branch stays under test over a usable origin. The assertions are unchanged: the scheme it stands in for, the dictionary registration, and the absent seat.

## Alternatives considered

**Declare the volatile App config fields first (issue #1717).** Rejected for this round, not on merit: the reporter is right that `dsh-remote-web-ui` and `dsh-usage` missed the 0.1.7 volatile migration, and both need their `Config` fields marked `.volatile()` plus reads through the live reference at the point of use. But `dsh-remote-web-ui`'s schema carries the pairing policy and a secret tunnel token, so changing it means touching a security surface that the round could not exercise in a real GUI. Recorded on the tracker as triaged with the concrete fix shape, to be landed as its own change.

**Fix the accessory rules for the context meter (issue #1715) by widening the selector.** Held back rather than rejected. `ContextMeter` renders as a sibling of the `conversation.composer.dock` slot host inside the shell's own `dock` container, so the shipped accessory rule (`… > *`, the slot's direct children) paints the statistics line but not the meter. Widening to the container (`[class*="_dock"] > *`) depends on a CSS-module hash; targeting the meter itself needs an anchor, and the installed bundle shows it carries only hashed class names and `aria-haspopup="dialog"`, no `data-*` semantic attribute. The third option — stop painting the statistics line too, so "accessory" means interactive accessory only — is a visual product decision. Asked the reporter which of the three to take.

**Widen the `peerDependencies` floor to admit `0.1.7-alpha.*` hosts (issue #1712).** Rejected: the alpha generation and the rc/stable generation differ in their client service surface (`settingsScope` was removed across exactly that boundary, which is what the reporter's 0.3.x entry was waiting for). Admitting alpha hosts would erase a correct incompatibility signal. The failure-isolation half of that request — one unactivated entry should not blank the whole page — is host behavior, outside this repository's plugin surface.

**Write the ledger's atomic rename retry to unblock the full-suite run.** Rejected as scope creep with a real risk of masking the defect: `packages/dsh-task-board` is byte-identical to `origin/dev` and its intermittent failures are Windows `EPERM` on `renameSync` of `ledger-v2.json`, unrelated to anything in this round. Fixing it means reasoning about the ledger's durability contract, which deserves its own change rather than a retry bolted on during triage.

## Consequences

The mobile drawer keeps a workspace group open when the operator expands it or opens its actions menu; selecting a session still folds it. A profile whose patch carried a three-line `ui-skin-*` row no longer has that file rewritten into invalid YAML, so the "next boot fails" loop is broken at the source — the fix reaches users through `dsh-skins`, and this repository's gitlink now pins it.

`pnpm test` no longer aborts on `dsh-update`; that package's 87 assertions run in the lanes that were previously reporting a worker-start failure.

Two known gaps are recorded rather than papered over. The intermittent `dsh-task-board` failures under a loaded full-suite run are pre-existing Windows `EPERM` on the ledger's atomic rename in `host-ledger.ts`; they reproduce on a package identical to `origin/dev`, pass in isolation, and are unrelated to this round. And the round's fixes were verified by unit tests: the drawer change was not exercised in a real narrow-viewport GUI, and no screenshot evidence accompanies it, which the tracker comment states explicitly.

Verification for this round: `pnpm typecheck`, `pnpm test` (all packages; the `dsh-task-board` flake above is the only interruption), `pnpm test:standards`, `pnpm docs:check`, `pnpm i18n:check`, `pnpm emoji:check`, `pnpm aggregate:check`, `pnpm libs:check`, plus the `dsh-skins` suite (701 tests) in its own repository. No `dsh web` restart is required for the host halves; the drawer change ships in the aggregate client bundle, so a page refresh picks it up once the bundles are rebuilt.
