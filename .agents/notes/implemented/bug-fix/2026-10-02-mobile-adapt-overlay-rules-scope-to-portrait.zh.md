# Agent Note: 竖屏适配层的设置弹窗规则改为只在竖屏 body class 下生效

Status: implemented

## Problem

Issue #1776 报告远程 Web UI 在手机上严重错位、而桌面本地界面正常，并怀疑
`dsh-claude-style`。但随附截图里并没有描述中的布局损坏：那是
`status.lanRequired` 提示——插件自己的"服务仅绑定在 127.0.0.1 且未配置
公网地址"卡片，属于绑定状态提示，不是布局故障。

在真实主机上复现报告中的组合，可以回答主题的疑问。一个装了
`@linxin666/dsh-remote-web-ui` 0.4.4 与 `dsh-claude-style` 0.10.1 的
scratch DSH，在 iPhone 13 视口下渲染出的竖屏布局是正确的：body 带上
`dsh-remote-portrait`，适配样式表就位，输入区老老实实待在卡片里，设置弹窗
是单列布局、顶部一排横向滚动的分区导航。同一次运行里做 A/B——移除
claude-style 样式表——输入区几何只随主题自身的装饰变化，并没有变成坏掉的
布局。主题不是触发因素。

同一次复现确实暴露了一个真实缺陷，只是离报告描述差了一层。v68 的设置弹窗
规则——`ADAPT_CSS` 中唯一会重排官方**双栏**表面的规则——没有带 body class
门控，而同一数组里的每一条抑制规则都带了。于是
`[class$="_overlay"] [class$="_panel"]` 只要注入的 `<style>` 标签还在
`<head>` 里就会命中，而同步 tick 会在与竖屏状态无关的情况下持续把标签补
回来。在真实 1440x900 主机上实测：官方设置面板本应是 `flex-direction: row`、
188 px 导航与 612 px 内容并排；套上这条无门控规则后变成
`flex-direction: column`，导航压到 236 px 高，内容撑满 800 px 并被挤到导航
下方。#1776 描述的"内容堆叠、被挤压"正是这条规则造成的结果——落在哪个视口
上，只取决于那个标签活到了哪里。

## Decision

`ADAPT_CSS` 中每一条设置弹窗规则都改为受 `body.dsh-remote-portrait` 门控，
与数组中已有的抑制规则一致。这个列布局切换是把桌面双栏面板改造成手机版，
只有 body 带竖屏 class 时才成立；共用的 overlay portal 在其他任何地方都必须
保持官方布局。

## Alternatives considered

- **删掉这些规则，让手机也保持 800 px 双栏面板。** 否决：面板是固定 800 px，
  塞进约 342 px 的手机视口里内容列会无法阅读。列切换本身是对的。
- **改为按标签本身收敛**（桌面时干脆不注入）。 否决：这个标签是页面级状态，
  同步 tick 会把它补回来，所以"标签在不在"不是"当前是竖屏"的可靠代理。
  给规则加门控让每条规则自解释且可测。
- **抬高主题的选择器权重、去改 `dsh-claude-style`。** A/B 已否决：装了主题
  竖屏布局就是正确的。为了修本包的规则去改另一个插件的层叠，反而会掩盖缺陷。

## Consequences

无论适配标签是否还在，桌面设置面板都保持官方双栏布局；手机仍是单列面板加
横向滚动导航。这些规则现在会在生成的 CSS 里带上
`body.dsh-remote-portrait`，因此今后往该分组新增规则必须同样带门控，否则
回归测试会失败。

## Required verification

在真实主机上、安装构建产物后，移动端与桌面端分别实测：

- 竖屏（iPhone 13，390x664）：body 带 `dsh-remote-portrait`，面板
  `flex-direction: column`，导航 342x52 位于内容 342x564 之上。
- 桌面（1440x900）：body 无竖屏 class，面板 `flex-direction: row`，导航
  188x800 与内容 612x800 并排。
- 修复前，桌面端注入该规则的同一次运行实测为
  `flex-direction: column`、导航 188x236、内容宽 800 且 y=286。

对话界面本身也一并验证过，不只是外壳：从手机发出的一条消息渲染为 186x42
的用户气泡（390 视口下右边缘 378），所在会话的头部激活了
`dsh-remote-header-seated`，无横向溢出，消息行、头部、标签行与输入区之间
没有相交的盒子。该次运行装有主题插件，也就是说手机端对话页在有主题的情况
下是正确的。
