# Agent Note: v0.4.0 release run

Status: implemented
Archived: 2026-09-30

## Problem

The family changed shape between 0.3.24 and this release. The skin collection, the pet plugin and the community plugin index moved into their own repositories and are consumed here as npm packages, and `dsh-doctor` and `dsh-tool-describe-image` left the family. Those package identities no longer exist in this repository, so the unified version line cannot stay on 0.3.x.

## Decision

Release 0.4.0 from `main`, with the three satellite repositories published first.

- The sixteen remaining family manifests and the root aggregate pin move to 0.4.0, and the lockfile specifier moves with them.
- The three satellite dependencies keep the `^0.3.24` range, which the satellites' own `0.3.25` satisfies, so the aggregate never pins a satellite to this line's version.
- Everything that embeds a version is regenerated in the same commit: the committed `dsh-market` and `dsh-web-all` bundles and the recorded source fingerprints. `market/dist` is rebuilt from the commits pinned in `market-inputs.lock.json` and verified.
- `docs/release-notes/v0.4.0.md` carries the bilingual notes the pipeline consumes.

## Compatibility audit

The change set's compatibility surface is the aggregate's mounting contract, and each face was verified before the tag:

- Row ids stay byte-identical, and the legacy subpath exports `./pet`, `./skin-center` and `./community-plugins` remain in the packed 0.4.0 manifest pointing at files the tarball contains, so an existing profile resolves them instead of failing with `ERR_PACKAGE_PATH_NOT_EXPORTED`. The same holds for the two packages removed from the family, each of which keeps a tombstone export.
- The registry path resolves: every `^0.3.24` satellite range in the packed manifest resolves to the published `0.3.25`, and the pipeline's `verify-registry` step asserts every family version before the Release is cut.
- Fresh install: the mount smoke boots the aggregate in a scratch `DSH_HOME` through the official CLI and headless-renders it, in both the registry mode and the `FAMILY_TGZS_DIR` mode that covers this repository's own builds.
- The upgrade path is verified after publication, because the target's exact 0.4.0 pins cannot resolve before the packages exist on npm: a scratch profile with the published 0.3.24 installed is upgraded to the published 0.4.0 and booted.

## Alternatives considered

**Stay on 0.3.x.** Rejected: three published identities disappear from this repository and three more leave the family, so a patch bump would misdescribe the release.

**Pin the satellites to an exact version.** Rejected: the satellites version on their own line, so an exact pin would force a family release for every satellite patch.

## Consequences

The aggregate depends on the satellites by range, so a satellite patch reaches users without a family release while a satellite breaking change needs a family release to move the range. The legacy `@linxin666/dsh-web-ui-all` package is deprecated and stays at its last published version; the migration window is closed and the pipeline no longer republishes it.
