# Agent Note: v0.4.0 发布历程

Status: implemented
Archived: 2026-09-30

## Problem

0.3.24 到本次发布之间，家族成员构成变了。皮肤集合、宠物插件与社区插件索引迁入各自的仓库并以 npm 包的形式被本仓消费，`dsh-doctor` 与 `dsh-tool-describe-image` 退出家族。这些包身份在本仓已不存在，统一版本线无法继续停在 0.3.x。

## Decision

从 `main` 发布 0.4.0，三个卫星仓先发版。

- 余下十六个家族清单与根聚合包钉版移动到 0.4.0，lockfile specifier 随之移动。
- 三个卫星依赖保留 `^0.3.24` 范围，由卫星自己的 `0.3.25` 满足，因此聚合包不会把卫星钉死在本版本线上。
- 所有内嵌版本号的产物在同一次提交里重新生成：已提交的 `dsh-market` 与 `dsh-web-all` bundle 以及记录的源码指纹。`market/dist` 依据 `market-inputs.lock.json` 固定的提交重建并校验。
- `docs/release-notes/v0.4.0.md` 携带发布管线直接采用的双语说明。

## 兼容性审计

本次改动集的兼容面就是聚合包的挂载契约，打 tag 前逐面核验：

- 行 id 逐字节保持不变，旧 subpath 导出 `./pet`、`./skin-center`、`./community-plugins` 仍在 0.4.0 的打包清单里，并指向 tarball 内真实存在的文件，因此既有 profile 能解析它们，而不会以 `ERR_PACKAGE_PATH_NOT_EXPORTED` 失败。退出家族的两个包同样各自保留 tombstone 导出。
- registry 路径可解析：打包清单里每个 `^0.3.24` 卫星范围都解析到已发布的 `0.3.25`，且发布管线的 `verify-registry` 步骤在创建 Release 之前断言每个家族版本都可解析。
- 全新安装：挂载冒烟经由官方 CLI 在 scratch `DSH_HOME` 里挂载聚合包并无头渲染，registry 模式与覆盖本仓自身构建的 `FAMILY_TGZS_DIR` 模式都跑。
- 升级路径在发布之后验证，因为目标包的精确 0.4.0 钉版在包不存在于 npm 之前无法解析：在一个已安装 0.3.24 的 scratch profile 上升级到已发布的 0.4.0 并启动。

## 备选方案

**继续停在 0.3.x。** 否决：三个已发布的包身份从本仓消失，另有三个退出家族，补丁版本号会错误描述这次发布。

**把卫星钉成精确版本。** 否决：卫星有自己的版本线，精确钉版会让每次卫星补丁都强制触发一次家族发布。

## Consequences

聚合包以范围依赖卫星，因此卫星的补丁无需家族发版即可到达用户，而卫星的破坏性改动需要家族发版来推进范围。旧的 `@linxin666/dsh-web-ui-all` 已弃用并停在上一个已发布版本；迁移窗口已关闭，发布管线不再重发它。
