本次发布给远程桥补上一条整页通道（§35 的 `ui.v1`）：agent 可以把一整页交给会话，用户在桌面端看到的是一张真正的页面卡，页面里的第一次操作作为该次调用的结果回到模型；不宣告 `ui.v1` 的客户端看到的握手与帧与从前完全一致。推送这一版修掉「同一台手机收到两条同样的通知」——发送前按 APNs 令牌收敛目标，一条令牌只投递一次；回合结束的公告也不再在帧到达时就发，而是等到该会话真正静默（宿主自己的运行标志、后代会话与宿主作业都停下）之后再发，最多等十分钟，超时就照发并在日志里写明当时还有什么在跑，因为「永远等不到的通知」正是这条通道要防的失败。桌面端的浏览器视图改用外壳发布的 Host 地址，`dsh-app:` 交付的页面不再拿自己的 scheme 去猜一个连不上的套接字。

> **协议仍是 v1，次版本 20 升到 21，纯追加**：`PROTO` 保持 1；`MINOR` 由 20 升到 21，只因多了一条 `ui.v1` 能力。hello 的能力表把协议自己的名字排在前面且保持原顺序，扩展插件注册的能力按注册表顺序追加并去重，所以没有挂载扩展的桥宣告的仍是它一直宣告的那份列表。
> **旧客户端零影响**：不宣告 `ui.v1` 的客户端拿到的握手、帧与话题都没有变化——整页卡只在声明了该能力的连接上出现。这一版没有删除任何帧、能力位或话题，推送存储的结构版本仍是 2，三条既有推送限额保持原值。
> **设备表的收敛是幂等的**：一台手机一行，重新配对只替换该行上的凭据；读取时把还残留的重复行收敛成「每个指纹一行、每条令牌一条登记」，并经名册自己的串行队列写回。收敛后的表再读一次是空操作（`compacted 0 duplicate row(s), retired 0 stale registration(s)`），可以重复执行。
> **本版没有重命名任何持久化或线协议标识符**：设置 section id、配置 key、localStorage 键、控制面 API path 与聚合行 id 全部保持原值；新增的都是纯追加。**没有手工迁移步骤**，正常升级即完成。
> **卫星范围这一版不动**：聚合包对四个卫星仓的依赖范围仍是 `^0.4.9`。卫星仓在各自仓库发布 `0.4.10` 并把聚合范围抬到 `^0.4.10`，是紧随其后的下一阶段，不在本次提交内。
> **转发的整页卡桌面端只渲染、不作答**：桌面端用 `srcdoc` 加 `sandbox=allow-scripts` 的受控 iframe 画出整页文档，页面发来的 `postMessage` 只换来一句可见提示，不转发、不落库、不发请求；超过 256 KiB 的页面不渲染并给出可见提示。
> **回合结束现在要等会话静默**：到达的 `turn/end` 先登记而不是直接发送，每五秒向宿主问一次「静默了吗」，最长等 600000 毫秒（十分钟）后照发，并在日志里记下当时仍在运行的东西。锁屏不会再在子会话还在跑的时候说「已经结束」。
> **判定「新回合」更严格**：只有能证明开启了一个新回合的增量才算数；子会话的落定通知以 agent 身份的 user 消息到达父会话，不再被当成新回合。
> **推送去重与既有契约**：发送前的目标按设备令牌收敛，重复登记的行在读取时收敛掉，schema 版本不变，没有引入新的帧、能力或话题。
> **已知限制：干净 profile 首次安装停在 `ERR_PNPM_IGNORED_BUILDS`，装上但不挂载**：在本机 pnpm 11.9.0 加官方 CLI 0.2.1-rc.3 下，干净 profile 首次用 `dsh plugin --profile <name> add` 装 `@linxin666/dsh-web-all@<version>` 以 exit 1 结束，唯一的报错是 `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: cloudflared@0.7.3, cpu-features@0.0.10, ssh2@1.17.0`。官方 CLI 只在安装命令 exit 0 之后才回写 profile（`dsh-plugin-manager` 的 `lib/types/operations.js:499` 附近），所以这次失败留下的是「家族包已写进 `package.json` 与锁文件、但 `dsh.profile.bundles` 里没有这一行」的状态：装上但不挂载，`--dump-config` 里看不到该 bundle，重跑同一条命令仍是同一个失败。出路有三条：把这三项写进 `<profile>/pnpm-workspace.yaml` 的 `allowBuilds`；或用官方 `--from-default-profile web` 重置 profile 后再 add（这两条本机实测都能成功挂载）；或安装时加 `--config.strictDepBuilds=false`。官方 CLI 只在 git 源插件失败时提示 `allowBuilds` 这一步，注册表包不提示；本仓 `pnpm-workspace.yaml:13` 的 `allowBuilds` 只作用于开发工作区，不作用于用户 profile。**这条限制不是本版引入的**：已发布的 0.4.9 同样复现，0.4.10 相对 0.4.9 没有新增运行时依赖，依赖未变时重复安装 exit 0，因此存量 profile 从 0.4.9 更新到 0.4.10 不受这道门影响；对 registry 上真版本的全量升级复跑放在发布之后。

- [remote-bridge] `ui.v1`：agent 可以把一整页交进会话，声明了该能力的客户端拿到 `ui.present`，页面里的第一次操作作为这次调用的结果回到模型

This release adds a whole-page channel to the remote bridge (§35's `ui.v1`): the agent can hand an entire page into the session, the desktop renders it as a real page card, and the first action inside that page comes back to the model as the result of the call. A client that does not declare `ui.v1` sees the handshake and the frames it always saw. Push delivery in this version fixes "one phone received the same notification twice": targets are converged by APNs token before fan-out, so one token is delivered once. A turn end is no longer announced when the frame arrives but once the session it belongs to falls quiet — the host's own running flag, any descendant session still running and any job the host attributes to either — waiting at most ten minutes and, at the limit, announcing anyway and logging what was still going, because a notification that never arrives is the failure this channel exists to prevent. The desktop browser view now uses the Host address the shell publishes, so a page delivered over `dsh-app:` no longer derives a socket from its own scheme that could never connect.

> **The protocol stays v1, the minor moves from 20 to 21, and the change is additive**: `PROTO` remains 1; `MINOR` moves from 20 to 21 only because there is one more capability, `ui.v1`. The hello capability list keeps the protocol's own names first and in their existing order, and appends the capabilities extensions registered in registry order, deduplicated, so a bridge with no extension mounted advertises exactly the list it always did.
> **No impact on older clients**: a client that does not declare `ui.v1` gets the handshake, the frames and the topics it got before — the whole-page card appears only on a connection that declared the capability. No frame, capability or topic is removed, the push storage schema stays at version 2, and the three existing push limits keep their values.
> **Converging the device table is idempotent**: one phone is one row, and pairing again only replaces the credential on the row the phone already has. A load converges whatever duplicates remain into one row per fingerprint and one registration per token, written back through the roster's own serialized queue. Reading the converged table again is a no-op (`compacted 0 duplicate row(s), retired 0 stale registration(s)`), so it is safe to repeat.
> **This version renames no persisted or wire-protocol identifier**: settings section ids, configuration keys, localStorage keys, control-plane API paths and aggregate row ids all keep their values; everything new is purely additive. **There are no manual migration steps**; a normal upgrade is all it takes.
> **The satellite ranges do not move in this version**: the aggregate's dependency ranges for the four satellites stay at `^0.4.9`. Publishing `0.4.10` from each satellite's own repository and raising the aggregate range to `^0.4.10` is the next stage that follows this one, and is not part of this commit.
> **The desktop renders a forwarded page but does not answer it**: the desktop draws the whole-page document in a controlled iframe built with `srcdoc` and `sandbox=allow-scripts`. A `postMessage` from the page only swaps in a visible hint — nothing is forwarded, stored or requested — and a page over 256 KiB is not rendered at all; a visible notice takes its place.
> **A turn end now waits for the session to fall quiet**: an arriving `turn/end` is registered rather than sent, the host is asked every five seconds whether the session is quiet, and at 600000 milliseconds (ten minutes) the announcement goes out anyway with a log line naming what was still going. A lock screen no longer says "finished" while a child session is still working.
> **What counts as a new turn is stricter**: only increments that prove a turn started are read as one. A child's settle notice arrives on the parent as a user message with an agent actor and is no longer mistaken for a new turn.
> **Push deduplication and the existing contract**: targets are converged by device token before fan-out and duplicate rows are converged when the table is read, with the schema version unchanged and no new frame, capability or topic introduced.
> **Known limitation: a clean profile stops at `ERR_PNPM_IGNORED_BUILDS` on its first install and lands installed but not mounted**: on this machine, under pnpm 11.9.0 with the official CLI 0.2.1-rc.3, a clean profile that runs `dsh plugin --profile <name> add` for `@linxin666/dsh-web-all@<version>` for the first time exits 1, and the only diagnostic is `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: cloudflared@0.7.3, cpu-features@0.0.10, ssh2@1.17.0`. The official CLI reconciles a profile only after an install that exited 0 (`dsh-plugin-manager`, around `lib/types/operations.js:499`), so this failure leaves the family package written into `package.json` and the lockfile with no row in `dsh.profile.bundles`: installed but not mounted, absent from `--dump-config`, and unchanged by running the same command again. There are three ways out: write the three names into `<profile>/pnpm-workspace.yaml` under `allowBuilds`; or reset the profile with the official `--from-default-profile web` and add again (both were measured here to mount the bundle); or pass `--config.strictDepBuilds=false` for the install. The official CLI prompts for the `allowBuilds` step only when a git-source plugin fails, not for a registry package, and this repository's own `allowBuilds` (`pnpm-workspace.yaml:13`) governs the development workspace and does not reach a user profile. **This version did not introduce the limitation**: the published 0.4.9 reproduces it, 0.4.10 adds no runtime dependency over 0.4.9, and a repeat install over an unchanged dependency set exits 0, so an existing profile updating from 0.4.9 to 0.4.10 is not affected by this gate; re-running the full upgrade against the published registry versions is scheduled after the release.
